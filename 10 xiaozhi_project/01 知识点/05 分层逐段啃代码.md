# 1. main
## 1.1 main.cc
##### 整体启动流程
```
芯片上电
  → FreeRTOS 内核启动
    → app_main()（本文件）
      ① esp_event_loop_create_default()    // 事件总线就绪
      ② nvs_flash_init()                    // 持久化存储就绪
      ③ Application::GetInstance().Start()  // 应用启动
            → 初始化硬件板子
            → 连接WiFi/4G网络
            → 建立WebSocket/MQTT到服务器
            → 开始音频处理管线（麦克风→编码→发送 / 接收→解码→扬声器）
```

**代码解析：**
```C++
auto& app = Application::GetInstance();  // 拿到那个唯一的"应用管理器"对象
app.Start();                             // 让它开始运转（初始化硬件、连接网络、开始语音交互）
```
**为什么要用单例？** 因为整个设备只需要一个"应用管理器"，它管理着音频服务、协议、显示、状态等所有全局资源。如果允许多个实例，会导致资源冲突（比如两个对象抢麦克风）。所以用私有构造 + 静态实例来强制"全局唯一"。
```
app.Start()
  ├── 创建事件组 event_group_（用 MAIN_EVENT_SCHEDULE、MAIN_EVENT_SEND_AUDIO 等标志）
  │     └── application.h 顶部宏：
  │         MAIN_EVENT_SCHEDULE        (1 << 0)   // 调度任务
  │         MAIN_EVENT_SEND_AUDIO      (1 << 1)   // 发送音频
  │         MAIN_EVENT_WAKE_WORD_DETECTED (1 << 2) // 唤醒词检测
  │         MAIN_EVENT_VAD_CHANGE      (1 << 3)   // VAD语音活动变化
  │         ...
  ├── 初始化硬件板子（通过 Board::GetInstance()）
  ├── 初始化 AudioService 音频服务
  ├── 创建定时器（clock_timer_handle_）
  ├── 创建 MainEventLoop 主事件循环任务
  └── 连接服务器，开始运行
```

#### 1.2.2 任务优先级管理类
**是什么：** 它是一个 RAII（Resource Acquisition Is Initialization，资源获取即初始化）惯用法的工具类，用来在某个作用域内临时改变当前 FreeRTOS 任务的优先级，离开作用域时自动恢复。
**作用：** 任务的优先级不是固定的，需要根据当前的运行状态动态调整，需要任务优先级管理类来动态调整。
```C
/* 任务优先级重置 */
class TaskPriorityReset {
public:
    TaskPriorityReset(BaseType_t priority) {  //构造函数
        original_priority_ = uxTaskPriorityGet(NULL);   //记录初始优先级
        vTaskPrioritySet(NULL, priority);   //设置新的优先级
    }
    ~TaskPriorityReset() {   //析构函数
        vTaskPrioritySet(NULL, original_priority_);  //还原优先级
    }
private:
    BaseType_t original_priority_;
};
```
**核心价值：** 
1. **保护临界操作不被抢占：** 确保临界操作在执行过程中不被更高优先级的任务打断（通过提高任务优先级），保证操作的原子性
2. **自动恢复优先级，零遗漏：** 利用RAII机制，在对象销毁的时候自动恢复优先级，无需手动恢复，避免遗漏导致优先级混乱
3. **异常安全：** 即使函数中途抛出异常，析构函数也会被调用，确保优先级被正确恢复，不会遗留优先级混乱的bug

# 1.
- **`"xxx.h"` vs `<xxx.h>`**：双引号优先在**当前目录**找，尖括号在**系统/编译器搜索路径**找。项目头文件用双引号，第三方/标准库用尖括号。

- **ESP-IDF 日志级别**：`ESP_LOGE`（错误）> `ESP_LOGW`（警告）> `ESP_LOGI`（信息）> `ESP_LOGD`（调试）> `ESP_LOGV`（冗余）。可以按 TAG 在 menuconfig 里单独控制级别。


```C++
static const char* const STATE_STRINGS[] = {.........};
```
- **`static`**：文件作用域，别的编译单元看不见这个变量。
- **`const char* const`** 两层 const：
    - 前面的 `const char*` 表示"指向的字符不可改"（字符串字面量本身就是只读的）
    - 后面的 `const` 表示"指针本身不可改"（不能 `STATE_STRINGS[0] = "xxx"`）


- **`std::list<std::function<void()>>`**：**为什么用 list 不用 vector**：list 插入 O(1)、不需要连续内存，而 vector 扩容要挪动全元素。Schedule 是高频插入 + 批量取出，list 更合适。


- 为什么需要资源 OTA？
	固件（.bin）升级慢、风险高。而**字体、表情、音效**这些资源经常变，如果每次改资源都刷固件，太麻烦。所以把资源放在独立的 **assets 分区**，通过 OTA 单独下载更新。
	ESP32 的 Flash 被划分成多个分区：
- `factory` / `ota_0` / `ota_1`：固件区
- `nvs`：键值存储（WiFi 密码、Settings）
- `assets`：资源区（字体/表情/音效）—— **本项目新增的分区**
- `spiffs` / `fat`：文件系统

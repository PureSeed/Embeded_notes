## 工程目录
**managed_components:** 组件管理器从乐鑫官网官方仓库自第三方库，组件即模块化的独立代码包。如：LCD,WIFI,按键
**docs：** 官方说明文档，主要包括各组件的api使用说明
**内存映射:** 把外设变成一段内存地址，读写地址就能操作硬件
**指令总线：** CPU专门用来读程序代码的通道，只运指令
**数据总线：** CPU专门用来读写变量，外设数据的通道，只运数据
**控制总线：** 告诉系统是要读取还是写入数据

#### 断电还在（SRMA 芯片内置高速内存）
**Flash：** 存完整程序
**ROM：** 厂家提前写好的底层启动代码，用户不能改，上电最先运行
#### 断电清空
**IRAM:** 放中断、高频执行的代码，只能4字节整块读取
**DRAM:** 存变量、数组、堆栈、堆内存、支持单字节读取
**RTC Fast/RTC Slow:** 休眠专用内存，深度休眠数据不丢失，一快一省电

**ICache（指令缓存）:** Flash速度慢，把常用代码提前存进ICache中，CPU直接高速读取指令，不用反复读Flash
**DCache（数据缓存）:** 缓存Flash中的常量，外部内存数据，加速数据读写，只存数据

#### 程序分区表
**Name（分区名称）：** 可自定义
**Type（分区类型）：** app（存程序），data（存数据）
**SubType（分区子类型）：** 
**Offset（偏移量）：** 这块分区在Flash中的起始地址
**Size（分区大小）：** 分配多少空间（4K/1M/0x2000等）
**Flags（分区标志）:** 区分加密和非加密

## 四层网络模型
**网络接口层：** 比如：**WiFi** ，负责物理传输，解决怎么把电信号传出去的问题。同一局域网内，硬件层面传输电/光信号。接口层只关心本地局域网，同局域网内传输就是接口层。网络层只管终点，不管途中每一站怎么传递，接口层专门管中途每一小段的传递，知道下一站去哪。依靠MAC地址完成相邻设备点对点传递，每经过一段局域网就更换一次MAC地址。
**网络层：** 比如：**IP地址** ，负责路径规划，解决数据该送到哪里的问题，区分不同主机，比如发到哪一台电脑，跨路由、跨局域网寻址，实现跨网段通信。
**传输层：** 比如：**TCP协议** ，负责可靠传输，解决数据怎么完整送达的问题，区分不同应用程序，比如是发到微信还是QQ。用端口号区分主机内的不同程序。
**应用层：** 比如：**HTTP** ，负责数据格式，解决数据怎么让应用程序看得懂的问题，区分不同的数据格式，比如是网页、图片还是视频。定义软件间的数据交互规则。

## HTTP
HTTP是互联网的通用语言，定义了应用之间沟通的规则，让不同设备和应用可以无障碍交流，

#### 工作流程：
1. **建立连接：** 客户端通过TCP协议与服务器建立连接
2. **发送请求：** 客户端告诉服务器想要的内容，==包括：请求行，请求头，请求体
3. **服务器处理请求：** 服务器找到对应的资源，
4. **返回响应：** 服务器把资源发给客户端，==包括：状态行，响应头，响应体
5. **关闭连接：** 数据传输完成后，关闭TCP连接。
----------------
## WebSocket
HTTP只有向服务器发送请求才会获得资源，需要不断的轮询才能获取最新消息，这样会增加服务器和网络负担且实时性不好。而WebSocket==可以提供低延迟的双向通信，可以让客户端和服务器保持持续连接，减少频繁建连开销。== 

**适用场景：** 
- **HTTP:** 适合一次性请求，比如：用户登录，获取历史消息，加载页面数据
- **WebSocket:** 适合持续推送，比如：实时接收新消息，实时状态变化，在线协作等互动性强的场景。

**WebSocket缺点：** 
- **对服务端压力大：** 大量在线连接，会变成服务器的压力
- 消息可靠性需要自己设计
- 连接管理更复杂
- 网络不稳定时要处理重连

### 回音消除（AEC）：
回音消除（Acoustic Echo Cancellation）是音频处理技术，用来消除扬声器声音被麦克风拾取产生的回音。一般通过宏定义决定消除回音的方式，可以再编译时根据不同的需求选择不同的AEC算法，或者直接关闭AEC功能。

**回音产生的原因：** 你的手机的扬声器播放对方的声音，这个声音被你的麦克风拾取，然后又传给对方，对方就听到了自己的回音
**原理：** 通过算法估计回音并从麦克风输入中减去。
      1. 当你的手机扬声器播放对方的声音的时，同时把这个声音的副本保存下来
      2. 当麦克风拾取声音的时候，把保存的扬声器声音副本从麦克风输入中减去

### 状态机
1. **启动中（kDeviceStateStarting）：** 初始化各个模块：显示屏、音频、网络等
2. **运行中（kDeviceStateRunning）：** 所有模块初始化完成，进入正常运行状态
3. **待机中（kDeviceStateStandby）：** 长时间没有用户操作，进入低功耗待机状态，节省电量
4. **升级中（kDeviceStateUpgrading）：** 检测到新版本固件，进入升级状态，禁止用户操作
5. **出错中：（kDeviceStateError）：** 设备出现故障，显示出错信息

### 音频
board.GetAudioCodec() 音频驱动初始化 → audio_service_.Initialize(codec) 音频服务初始化 → audio_service_.Start() 音频服务启动 
· 采集任务：MIC→Opus编码→发送队列
· 播放任务：接收队列→Opus解码→喇叭
→ 注册回调（队列就绪/唤醒词/VAD）

### 音频采集与播放全流程
1. **麦克风（MIC）：** 把声音变成连续变化的电信号
2. **ADC：** 把模拟电压信号变成数字信号
3. **I2S:** 专门用来传输数字音频信号，传输到单片机芯片中
4. **OPUS编解码：** 压缩与还原音频，把大体积的音频数据压缩成小体积的数据包
5. **WIFI:** 通过WIFI把数据包传输到云端服务器
6. **云端服务器：** 识别语音，生成回答的音频数据，并用OPUS压缩，再通过WIFI传回去
7. **OPUS编解码：** 还原音频，把压缩的数据包还原成数字音频信号
8. **MAX98357音频放大器:** I2S把数字音频信号传输到MAX98357音频放大器中，**内部的DAC：** 把数字信号变回模拟信号。DAC输出的模拟电压信号功率太小，需要通过音频放大器把功率放大
9. **喇叭：** 把模拟电压信号变回声音

### 四种事件系统
**ESP32系统事件：** 负责硬件相关的事件，比如：WIFI连接、蓝牙配对、IP地址获取
**FreeRTOS事件：** 负责协调任务之间的工作，事件标志组、消息队列，负责任务中间的通信
**LVGL事件：** UI事件系统，负责用户UI界面交互事件，比如：按钮点击、屏幕触摸
**应用层事件：** 负责处理业务逻辑相关的事件

**中断和事件的区别：** 
**中断：** 硬件触发，最高优先级必须立即处理，快速结束。中断保证实时性
**事件：** 软件触发，优先级低可以慢慢处理，复杂逻辑。事件保证灵活性和可维护性

**中断不能做的事情：** 
1. 不能调用阻塞函数，比如：xTaskDelay()、xQueueSend()
2. 不能进行复杂计算
3. 不能调用非线程安全函数，比如：printf()

**中断中应该做的事情：** 
1. **设置标志位：** 告诉主程序有事件发生了
2. **发送事件到队列：** 把中断中接收到的数据放到队列中，让主程序去处理
3. **清除中断标志位** 

**具体例子：** 
1. **裸机中断：** 用户长按配网按键触发中断，中断服务程序设置“配网请求”标志位
2. **FreeRTOS事件：** main_event_loop核心调度任务清除标志位，发送配网事件到应用层
3. **应用层中断：** 应用层任务发送WIFI配网请求和UI更新事件到应用层队列
4. **ESP32系统事件：** 启动配网模式
5. **LVGL事件：** 更新配网状态UI
6. **应用层事件：** 进入运行状态

### JSON（JavaScript Object Notation)
JSON本质是一门统一的数据语言，解决的是不同系统之间能无障碍交流数据。不同系统用的是不同数据语言，比如说：嵌入式设备用二进制指令，手机APP用XML格式数据，云端服务器用CSV表格存储信息，而JSON相当于数据世界的普通话，是通用数据语言。

它比XML更简洁，比二进制格式更易读

**解决的核心需求：** 打破不同系统之间的数据交流壁垒，JSON让数据成为了流动的资产，以前数据被锁在各个系统里面很难共享和使用，有了JSON之后，数据可以在不同系统之间自由流动。

### CMake
它是项目构建工具，负责管理项目的编译流程和依赖关系，告诉编译器怎么编译代码。
编译器负责把代码变成可执行文件，而CMake负责告诉编译器怎么编译代码。CMake负责策划，编译器负责执行
**解决的核心问题：** 
1. **跨平台编译：** 在它诞生之前，不同的编译平台、不同的编译器的编译方式完全不同。Linux用Makefile，嵌入式用Keil/IAR工程。而CMake可以统一编译配置，用一套CMake脚本管理所有平台的编译配置，一次编写，到处编译。解决跨平台编译的复杂性。
2. **管理依赖关系：** 自动处理库文件和头文件的依赖关系，无需手动编译
3. **支持多板型编译：** 通过条件编译指令，为不同板型生成不同的编译配置。
4. **简化编译流程：** 一条命令就能完成编译、链接、生成固件的全流程。

### MCP（Multi-Control Protocol)
本质是一套标准化的硬件控制指令集
**核心作用：** 让云端和设备用统一的MCP协议对话，实现“一句话控制硬件”。MCP统一了硬件控制接口，降低云端开发成本，提高硬件拓展性
**解决的问题：** 不同的硬件有不同的控制接口，云端需要适配各种硬件

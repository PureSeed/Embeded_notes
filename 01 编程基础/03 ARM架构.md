# ARM芯片程序执行完整流程
#### FLASH: 
**编译好的程序会被烧录到FLASH存储器里，** FLASH就相当于电脑的硬盘，断电后数据不会丢失，而且可以反复擦写，不过擦写次数确实有限，一般在10万次左右。FLASH的读取速度比较慢，大概在几十兆字节每秒，所以CPU不会直接从FLASH里读取指令来执行，那样会严重影响程序运行速度。
#### RAM:
芯片上电启动的时候，首先会运行启动代码，**启动代码会把FLASH里的程序复制到RAM里。** RAM就相当于电脑的内存，读写速度非常快，一般可以达到几百兆字节每秒，而且可以随机访问，CPU可以快速从RAM里读取指令和数据。不过RAM断电后数据会丢失，所以程序不能一直存在RAM里，必须保存在FLASH里。 
**RAM在程序运行过程中主要有两个作用：** 
一是存储程序指令，CPU从RAM里读取指令来执行；
二是存储全局变量、堆、栈这些运行时数据。全局变量和静态变量会被分配到RAM的全局数据区，堆是程序运行时动态分配内存的区域，栈是函数调用时用来保存局部变量和函数返回地址的区域。
#### CPU:
最后就是CPU的执行流程了，CPU会从RAM里读取指令，放到指令寄存器里，然后指令译码器会把指令翻译成CPU能理解的操作，接着把操作数从RAM里读取到通用寄存器里，然后ALU（算术逻辑单元）执行计算，最后把计算结果写回RAM或者寄存器里。整个过程周而复始，直到程序执行完毕。
 
#### 内存的五大核心区域
RAM在程序运行时会被自动划分为五个核心区域，每个区域都有明确的功能和用途：
1. **代码段（.text）** 
**代码段就是存储程序指令的区域，** 你写的所有C函数的机器指令都会存放在这里。芯片上电启动后，启动代码会把FLASH里的代码段复制到RAM的代码段区域，CPU就从这里读取指令来执行。代码段是只读的，程序运行过程中不会被修改，这样可以防止程序指令被意外破坏。
2. **全局数据段（.data）** 
**全局数据段存储的是已经初始化的全局变量和静态变量。** 比如你定义了  int global_var = 10; ，这个变量就会被分配到全局数据段，它的初始值10会被存储在FLASH里，启动时会被复制到RAM的全局数据段。全局数据段是可读写的，程序运行过程中可以修改这些变量的值。
3. **未初始化数据段（.bss）** 
**未初始化数据段存储的是未初始化的全局变量和静态变量。** 比如你定义了  int global_var; ，这个变量就会被分配到未初始化数据段。程序启动时，启动代码会自动把这个区域的所有数据初始化为0，所以未初始化的全局变量默认值都是0。这个区域不会占用FLASH空间，因为它不需要存储初始值，只需要在启动时初始化即可。
4. **堆（Heap）** 
**堆是程序运行时动态分配内存的区域，你调用  malloc() 、 calloc()  这些函数分配的内存都会从堆里获取。** 堆的大小是可以动态调整的，从低地址向高地址增长。不过堆的管理需要你自己负责，分配的内存使用完之后必须调用  free()  释放，否则会导致内存泄漏，最终耗尽RAM空间。
5. **栈（Stack）** 
**栈是函数调用时用来存储局部变量和函数返回地址的区域，** 它由CPU自动管理，不需要你手动分配和释放。栈从高地址向低地址增长，每次调用函数时，CPU都会把函数的返回地址、参数和局部变量压入栈中；函数执行完毕后，CPU会把这些数据弹出栈，回到调用函数的地方继续执行。栈的大小是固定的，在链接脚本中定义，如果函数调用层次太深或者局部变量太多，就会导致栈溢出，程序崩溃。

#### RAM内存布局的顺序
从低地址到高地址，RAM的布局顺序一般是：代码段 → 全局数据段 → 未初始化数据段 → 堆 → 栈。堆从低地址向高地址增长，栈从高地址向低地址增长，它们之间有一个空闲区域，**当堆和栈增长到相遇时，就会发生内存溢出，程序崩溃。** 
 
#### 理解内存布局的实际意义
理解RAM的内存布局对嵌入式开发非常有帮助：比可以通过查看内存使用情况来优化程序，避免内存浪费；当程序出现崩溃时，可以通过分析内存布局来定位问题，比如是栈溢出还是堆内存泄漏；还可以根据内存布局来合理分配变量，比如把频繁访问的变量放在全局数据段，减少缓存失效的概率。

**代码区：** 这里存的不是你写的源代码，而是编译之后的机器指令，就是CPU能直接看懂的二进制代码。这些代码会被烧录到芯片的Flash里面，很多嵌入式芯片支持直接在Flash里运行代码，不需要复制到内存里，这样就能节省宝贵的RAM空间。而且这个区域会被硬件设置成只读的，防止程序运行的时候不小心改到了指令，导致系统崩溃。多个程序还可以共享同一段代码。
 
**数据区：** 这里面其实分成了三个部分。**第一部分是已初始化的数据区，** 放那些你在代码里已经给了初始值的全局变量和静态变量，程序一启动就会把这些值加载到内存里。**第二部分是未初始化的数据区，** 这里的变量会被系统自动初始化成0或者空值，你不用手动给它们赋值。**第三部分是常量区，** 专门放字符串常量和用const修饰的变量，这个区域一般也会被设置成只读，防止程序运行中被意外修改。
 
**栈区：** 这个区域是完全自动管理的，你不用手动申请和释放内存。每次调用函数的时候，系统都会在栈上创建一个栈帧，**用来存放函数的局部变量、函数参数和返回地址。** 栈的工作方式是先进后出。嵌入式里的栈空间一般都很小，大多只有几KB到几十KB，如果你写了一个递归调用很深的函数，或者在函数里定义了特别大的数组，就很容易把栈撑爆，造成栈溢出错误，这是嵌入式开发里非常常见的问题。

**堆区：** 必须用malloc手动申请，用free手动释放。内存块是不连续的
 
ARM架构的内存布局图，低地址是用户空间，高地址是内核空间。**栈是从高地址往低地址生长的，堆是从低地址往高地址生长的，它们中间有一块空闲区域，要是两个区域碰到一起了，就会发生内存溢出，程序就会崩溃。** 

---------------

Flash就像是嵌入式设备的硬盘，负责存储断电也不会消失的静态数据；RAM就是运行内存，专门放程序运行时需要快速读写的数据。

**首先是Flash，** 它里面主要放两个分区。**第一个就是代码区，** 写好的程序编译之后就烧录在这里，断电之后代码也不会消失。很多嵌入式芯片支持XIP技术，可以直接在Flash里运行代码，不用复制到RAM里。**第二个是只读数据区，** 这里放常量、和const修饰的变量，这些不会变的数据，程序运行的时候只能读取不能修改。

**然后就是RAM，** 程序运行时所有需要动态修改的数据都在这里。**第一个是数据区，程序启动的时候，Flash里初始化好的全局变量和静态变量会被复制到这里，未初始化的变量也会在这里分配空间并且自动清零。** **第二个是栈区，** 用来存放函数的局部变量、函数参数和返回地址。栈的空间大小是固定的，一般在链接脚本里配置，程序运行时由CPU自动管理，不需要程序员手动操作。**最后是堆区，** 这是RAM里剩下的空闲内存，由程序员手动申请和释放，用来创建动态的数据结构，比如链表、队列这些。
 
几个设计规则：第一，Flash读写速度慢，但是可以永久保存数据，**所以只放那些不经常修改的静态内容。** 第二，RAM读写速度非常快，但是断电就丢数据，**所以专门用来放程序运行时需要快速读写的数据。** 第三，有些对运行速度要求特别高的代码，可以复制到RAM里运行，这样能比在Flash里快很多。第四，栈和堆只能放在RAM里，因为它们需要频繁的分配和释放，Flash的擦写速度根本跟不上。

**读取速度：寄存器> RAM > FLASH** 
故把需要频繁访问的变量优化到寄存器中
把只读的数据放到Flash中节省RAM内存
把大数组放在堆区，避免栈溢出

**单片机编程的本质，就是通过操作寄存器来指挥硬件工作** 
**CPU：** 每个寄存器都有唯一的地址，CPU通过读写这些地址来控制系统
**总线：** 根据地址把数据传到正确的地方
**外设：** 根据信号执行相应的动作

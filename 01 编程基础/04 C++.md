## 1.4 引用
引用即别名，引用不可修改,创建时就必须初始化（赋值）
```C++
/* 数据类型& 引用名 = 被引用变量 */
int a = 10;
int& b = a;

/* 
 * 值传递：会复制值，无法对实参本身产生影响
 * 地址传参：会复制地址，对实参本身有影响，但是指针写法麻烦
 * 引用传参：像普通变量那样操作，但对实参本身可以产生影响 
 */
```

引用变量是一个别名，也就是说，它是某个已存在变量的另一个名字。
一旦把引用初始化为某个变量，就可以使用该引用名称或变量名称来指向变量。
引用必须在定义时初始化，并且一旦绑定到一个变量后，就不能再绑定到其他变量。
引用的语法如下：
```C++ 
int a = 10;
int &ref = a;  // ref 是 a 的引用
```
- `int &ref` 表示 `ref` 是一个 `int` 类型的引用。
- `ref` 是 `a` 的别名，对 `ref` 的操作会直接作用于 `a`。

**引用和直接操作原对象的区别：** 
1. 引用可以让你在不同的作用域操作另一个作用域的对象，而不需要知道另一个对象的具体位置。
2. 引用让代码更安全，因为引用必须绑定到一个合法对象，不能为null，所以你不用担心空指针的问题，而指针可以为null，使用的时候必须先检查是否为null，否则会导致程序崩溃。

**引用的作用：** 
1. **简化长变量名：** 给复杂的变量名起短别名，让代码更简洁易读 
2. **避免拷贝大对象：** 直接引用原对象，不拷贝，大大提高程序运行效率（C++默认值传递，编译器会自动拷贝实参，创建临时对象。而引用传递不拷贝）
3. **让函数修改实参：** 不用指针也能让函数修改传入的参数

#### C++ 引用 vs 指针
引用很容易与指针混淆，它们之间有三个主要的不同：
- 不存在空引用，引用必须连接到一块合法的内存。
- 一旦引用被初始化为一个对象，就不能被指向到另一个对象。指针可以在任何时候指向到另一个对象。
- 引用必须在创建时被初始化。指针可以在任何时间被初始化。
- 引用的对象必须是一个变量，而指针必须是一个地址。

| **特性**              | **引用**                                            | **指针**                                                      |
| ------------------- | ------------------------------------------------- | ----------------------------------------------------------- |
| **定义与初始化**          | 必须初始化，且不能为 `null`。                                | 可以不初始化，可以在后续代码中指向其他对象，可以为 `null`。                           |
| **语法**              | 使用 `&` 声明，例如：`int &ref = a;`                      | 使用 `*` 声明，例如：`int *ptr = &a;`                               |
| **重新绑定**            | 不能重新绑定，一旦初始化后始终引用同一个对象。                           | 可以重新指向其他对象，例如：`ptr = &b;`                                   |
| **空值（Nullability）** | 不能为 `null`，必须绑定到有效的对象。                            | 可以为 `null`，表示不指向任何对象。                                       |
| **内存占用**            | 不占用额外内存（编译器通常将其优化为直接操作所引用的对象）。                    | 占用额外内存（存储地址，通常是一个机器字长，如4字节或8字节）。                            |
| **访问方式**            | 直接使用，无需解引用操作符，例如：`ref = 10;`                      | 需要使用 `*` 解引用操作符访问或修改所指向的对象，例如：`*ptr = 10;`                  |
| **多级间接访问**          | 不支持多级间接访问（不能有引用的引用）。                              | 支持多级间接访问（如指针的指针：`int **pptr;`）。                             |
| **函数参数传递**          | 常用于函数参数传递，语法简洁，例如：`void func(int &x) { x = 10; }` | 也可以用于函数参数传递，但需要使用解引用操作符，例如：`void func(int *x) { *x = 10; }` |
| **数组与引用**           | 不能直接创建引用数组，但可以创建数组的引用，例如：`int (&ref)[10] = arr;`  | 可以创建指针数组，也可以创建指向数组的指针，例如：`int *ptrArr[10];`                 |
| **安全性**             | 更安全，不能为 `null`，且语法更直观。                            | 更灵活，但容易出错（如空指针、野指针等）。                                       |
| **底层实现**            | 通常通过指针实现，但编译器会优化为直接操作所引用的对象。                      | 直接存储目标对象的内存地址。                                              |

## 1.5 const
```C++
/* 1. 修饰普通变量 */
const int a = 10;  // a只能读，不能改

/* 2. 修饰指针 */
const int* p;  // 等价 int const *p,指向的内容只读，不能改，但p本身可以改，可以指向其他地址
int* const p;  // 指针本身不能改指向，但是*p的内容可以修改
const int* const p;  //指针本身和指向的内容都不能改

/* 3. 修饰函数参数 */
void func(const std::vector<int>&v)
{
	// v里面的元素不能修改，防止函数内部不小心改动外面传进来的数据
}

/* 4. 修饰成员函数，其目的是防止成员函数修改被调用对象的值 */
class Test
{
	public:
		void show() const   //只读函数，只能读对象的数据，不能修改对象
		{
			//这个函数承诺：不会修改这个对象的成员变量。在这个函数里面不能给成员赋值
		}
}
```
const对象只能调用带const的成员函数

## 1.6 inline
**解决的问题：** 为了解决一些频繁调用的小函数大量消耗栈空间（栈内存）、函数本身调用开销（压栈、跳转、返回）比在函数里面干的活还多的问题，特别的引入了 inline 修饰符，表示为内联函数。
- 栈空间就是指放置程序的局部数据（也就是函数内数据）的内存空间。
- 在系统下，栈空间是有限的，假如频繁大量的使用就会造成因栈空间不足而导致程序出错的问题，如，函数的死循环递归调用的最终结果就是导致栈内存空间枯竭。
- inline就是给编译器建议，尽量不要生成函数调用，而是把这个函数的代码原地展开、插到调用的地方
- inline 的使用是有所限制的，inline 只适合函数体内代码简单的涵数使用，不能包含复杂的结构控制语句例如 while、switch，并且不能内联函数本身不能是直接递归函数（即，自己内部还调用自己的函数）。
- inline 函数仅仅是一个对编译器的建议，所以最后能否真正内联，看编译器的意思，它如果认为函数不复杂，能在调用点展开，就会真正内联，并不是说声明了内联就会内联，声明内联只是一个建议而已。
- 因为内联函数要在调用点展开，所以**编译器必须随处可见内联函数的定义**。所以，这要求每个调用了内联函数的文件都出现了该**内联函数的定义**。因此，将**内联函数的定义**放在**头文件**里实现是合适的，省却你为每个文件实现一次的麻烦。**如果不放到头文件的话，声明跟定义要一致**：如果在每个文件里都实现一次该内联函数的话，那么，最好保证每个定义都是一样的，否则，将会引起未定义的行为。如果不是每个文件里的定义都一样，那么，编译器展开的是哪一个，那要看具体的编译器而定。所以，最好将**内联函数定义**放在**头文件**中。 
- **定义**在类中的**成员函数**默认都是**内联的**，如果在类定义时就在类内给出函数定义，那当然最好。如果在类中未给出成员函数定义，而又想内联该函数的话，那在类外要加上 inline，否则就认为不是内联的。
- 关键字 inline 必须与函数定义体放在一起才能使函数成为内联，仅将 inline 放在函数声明前面不起任何作用。所以说，inline 是一种"**用于实现的关键字**"，而不是一种"用于声明的关键字"。一般地，用户可以阅读函数的声明，但是看不到函数的定义。尽管在大多数教科书中内联函数的声明、定义体前面都加了inline 关键字，但我认为**inline不应该出现在函数的声明中**。这个细节虽然不会影响函数的功能，但是体现了高质量C++/C 程序设计风格的一个基本原则：**声明与定义不可混为一谈，用户没有必要、也不应该知道函数是否需要内联。**
- 内联是以**代码膨胀（复制）**为代价，仅仅省去了函数调用的开销，从而提高函数的执行效率。   
如果执行函数体内代码的时间，相比于函数调用的开销较大，那么效率的收获会很少。另一方面，每一处内联函数的调用都要复制代码，将使程序的总代码量增大，消耗更多的内存空间。（以代码段空间换调用时间）
**以下情况不宜使用内联：**   
（1）如果函数体内的代码**比较长**，使用内联将导致**内存消耗代价较高**。   
（2）如果函数体内出现**循环**，那么执行函数体内代码的时间要比函数调用的开销大。类的构造函数和析构函数容易让人误解成使用内联更有效。要当心**构造函数和析构函数可能会隐藏一些行为**，如"偷偷地"执行了**基类或成员对象**的构造函数和析构函数。所以**不要随便地将构造函数和析构函数的定义体放在类声明中**。一个好的编译器将会根据函数的定义体，自动地取消不值得的内联（这进一步说明了 inline 不应该出现在函数的声明中）。

**在嵌入式中的适用场景：**
1. **硬实时、高频调用极小工具函数：** 比如在中断服务函数里面、或者高频循环里面反复调用的一两行工具。中断里面本身就要去越快结束越好，所以有时候会牺牲一点Flash
2. **模板函数、头文件中的泛型工具：** 不是为了提速，是语法需求。模板函数本来就要写在头文件，不加inline会报多重定义，这里inline是解决链接报错，属于语法问题（这个是因为C++的单定义特性有关，链接器默认一个全局符号，只能有一份定义。inline告诉连接器：这个符号允许多份一模一样的定义，你不要报错，选其中一份就行，其余丢掉）

## 1.8 lambda函数与表达式
**解决的核心问题：** 不用单独在外面定义一个有名字的函数，直接在当前代码位置，直接写一段可执行逻辑；并且能直接捕获当前作用域里的局部变量。
它本身没有函数名，用完即扔，适合短小逻辑，它不是函数，本质上是编译器自动帮你生成一个匿名仿函数类，然后当场创建这个类的对象。
```C++
[捕获列表](参数列表)mutable-> 返回类型{函数体};
/* []: 捕获列表，拿外面当前作用域的变量
 * [=]: 值捕获，把外面变量拷贝一份给lambda，只读
 * [&]: 引用捕获，直接引用外面原始变量，修改会影响外面
 * [a]: 值捕获变量a
 * [&a]: 引用捕获变量a
 * mutable：可选，如果只是值捕获，那就不能修改捕获进来的值，加mutable才允许修改
 */

auto add = [](int a, int b)
{
	return a+b;
}
```
**优势：**
1. **就地写逻辑，代码不割裂：** 不需要到别的地方单独定义命名函数，任务入队那一行，直接写任务代码，看代码的时候不用来回翻文件找回调函数
2. **可以捕获当前局部变量，大幅减少全局变量：** 用完即弃，避免命名冲突、多任务竞态、污染全局命名空间

## 1.9 智能指针
**智能指针 = 套了一层RAII外壳的普通指针** ，智能指针依靠RAII机制：对象构造时接管堆内存，智能指针销毁（出作用域）的时候，自动释放内存。靠生命周期自动管理堆内存
用于自动管理动态分配的内存。智能指针的主要类型有：
- `std::unique_ptr`：独占所有权的智能指针，同一时间只能有一个 `unique_ptr` 指向特定内存。
- `std::shared_ptr`：共享所有权的智能指针，多个 `shared_ptr` 可以指向同一内存，内存在最后一个 `shared_ptr` 被销毁时释放。
- `std::weak_ptr`：弱引用智能指针，用于与 `shared_ptr` 配合使用，避免循环引用导致的内存泄漏。

**使用 `std::unique_ptr`(常用)** 
```C++
class MyClass {  
public:  
    void doSomething() {  
        std::cout << "Doing something" << std::endl;  
    }  
};  
  
int main() {  
    std::unique_ptr<MyClass> myPtr(new MyClass());  
    myPtr->doSomething(); // 使用智能指针调用成员函数  
  
    // 当 main 函数结束时，myPtr 被销毁，自动释放 MyClass 对象的内存  
    return 0;  
}  
```
输出结果：Doing something

**使用 `std::shared_ptr`** 
```C++
class MyClass {  
public:  
    void doSomething() {  
        std::cout << "Doing something" << std::endl;  
    }  
};  
  
int main() {  
    std::shared_ptr<MyClass> myPtr1(new MyClass());  
    std::shared_ptr<MyClass> myPtr2 = myPtr1;  
  
    myPtr1->doSomething(); // 使用 myPtr1 调用成员函数  
    myPtr2->doSomething(); // 使用 myPtr2 调用成员函数  
  
    // 当 myPtr1 和 myPtr2 都被销毁时，MyClass 对象的内存才会被释放  
    return 0;  
}  
```
输出结果：
Doing something
Doing something

**使用 `std::weak_ptr`**
`std::weak_ptr` 通常不单独使用，而是与 `std::shared_ptr` 结合使用，以解决循环引用问题。
```C++ 
class Node {  
public:  
    std::shared_ptr<Node> next;  
    std::weak_ptr<Node> prev;  
  
    Node() : next(nullptr), prev() {}  
};  
  
int main() {  
    std::shared_ptr<Node> node1 = std::make_shared<Node>();  
    std::shared_ptr<Node> node2 = std::make_shared<Node>();  
  
    node1->next = node2;  
    node2->prev = node1;  
  
    // 循环引用，但使用 weak_ptr 避免了内存泄漏  
    return 0;  
}  
```
在这个例子中，`node1` 和 `node2` 形成了循环引用。由于 `prev` 是 `weak_ptr`，当 `node1` 和 `node2` 的 `shared_ptr` 被销毁时，它们指向的内存也会被正确释放。

# 2. 面向对象编程
## 2.1 类与对象
一个新的结构类，可以封装**属性和行为（函数）**
类就像是一个设计图，而对象就是基于类得到的具体实例
```C++
class class_name
{
	public:   // 公开权限，产出的具体对象，可以使用类的成员
	private:   // 私有权限，产出的具体对象，不可以使用类的成员。外部调用不了，但是内部的public可以调用
	protected:   // 保护权限
}
```

```C++
class Box
{
   public:
      double length;   // 长度
      double breadth;  // 宽度
      double height;   // 高度
      // 成员函数声明
      double get(void);
      void set( double len, double bre, double hei );
};
// 成员函数定义
double Box::get(void)
{
    return length * breadth * height;
}
 
void Box::set( double len, double bre, double hei)
{
    length = len;
    breadth = bre;
    height = hei;
}
```
**对象的生命周期：** C++对象的生命周期由作用域自动管理，不需要手动创建和销毁。
1. **创建对象：** 在某个作用域（比如：函数）中创建一个对象时，对象就进入了这个作用域。
2. **自动销毁：** 当对象离开这个作用域时（函数执行完毕），对象会自动销毁，不用手动调用销毁函数。对象销毁2时，它的析构函数会自动被调用。


### 2.1.1 构造函数和析构函数
**构造函数：** 负责在对象诞生的时候做好初始化工作。比如：给对象的成员变量设置初始值，给它分配内存等
**析构函数：** 在对象被销毁前帮它完成最后的清理。比如：释放之前分配的内存
**本质：** 管理对象的生命周期，不仅仅是创建和销毁对象，只要是在对象创建是执行初始化操作，对象销毁时执行清理操作
**作用:** 
1. **确保对象始终有效：** 确保对象始终处于有效状态，避免对象处于未初始化的危险状态
2. **自动管理资源：** 避免内存泄漏或资源浪费问题
3. **简化代码逻辑：** 把初始化和清理逻辑封装起来，提高代码复用性
```C++
class Person
{
	// 1. 构造函数: 函数名和类名相同；无返回值也不用写void；可以有参数，可以重载
	Person()
	{	
	}
	// 2. 析构函数：函数名和类名相同；无返回值也不用写void；不可以有参数，不可以重载
	Person()
	{
	}
}
```
#### 拷贝构造函数：
用一个已经存在的对象来创建一个新对象（可以理解成复制粘贴）。**拷贝构造函数**是一种特殊的构造函数，它在创建对象时，是使用同一类中之前创建的对象来初始化新创建的对象。
如果在类中没有定义拷贝构造函数，编译器会自行定义一个（浅拷贝）。如果类带有指针变量，并有动态内存分配，则它必须有一个拷贝构造函数。拷贝构造函数的最常见形式如下：
```C++
/* 形式 */
classname (const classname &obj) {  //obj是一个对象引用，该对象是用于初始化另一个对象的。
   // 构造函数的主体
}

/* 禁止拷贝 */
Application(const Application&) = delete;
Application& operator=(const Application&) = delete;
```
**深拷贝：** 创建独立的内存空间，但会占用更多的内存和时间，安全但成本高
**浅拷贝：** 共享内存，高效但可能导致内存问题

**有参构造函数：** 创建对象时传入参数，自定义初始化值
**无参构造函数：** 创建对象时不需要传参数，使用默认值初始化



### 2.1.2 this 
在 C++ 中，**this** 指针是一个特殊的指针，它指向当前对象的实例。每一个对象都能通过 **this** 指针来访问自己的地址。
**this是当前对象的变量，不是当前函数的局部变量** 
**this**是一个隐藏的指针，可以在类的成员函数中使用，它可以用来指向调用对象。
当一个对象的成员函数被调用时，编译器会隐式地传递该对象的地址作为 this 指针。

## 2.2 继承
继承允许我们依据另一个类来定义一个类，当创建一个类时，您不需要重新编写新的数据成员和成员函数，只需指定新建的类继承了一个已有的类的成员即可。这个已有的类称为**基类**，新建的类称为**派生类** 
```C++
// 基类
class Animal {
    // eat() 函数
    // sleep() 函数
};

//派生类
class Dog : public Animal {
    // bark() 函数
};
```

一个类可以派生自多个类，这意味着，它可以从多个基类继承数据和函数。定义一个派生类，我们使用一个类派生列表来指定基类。类派生列表以一个或多个基类命名如下：，实例如下：
```C++
// 基类
class Shape 
{
   public:
      void setWidth(int w)
      {
         width = w;
      }
      void setHeight(int h)
      {
         height = h;
      }
   protected:
      int width;
      int height;
};
 
// 派生类
class Rectangle: public Shape  //形式：class derived-class: access-specifier base-class
{
   public:
      int getArea()
      { 
         return (width * height); 
      }
};
```

| 访问   | public | protected | private |
| ---- | ------ | --------- | ------- |
| 同一个类 | yes    | yes       | yes     |
| 派生类  | yes    | yes       | no      |
| 外部的类 | yes    | no        | no      |
我们几乎不使用 **protected** 或 **private** 继承，通常使用 **public** 继承。当使用不同类型的继承时，遵循以下几个规则：
- **公有继承（public）：**当一个类派生自**公有**基类时，基类的**公有**成员也是派生类的**公有**成员，基类的**保护**成员也是派生类的**保护**成员，基类的**私有**成员不能直接被派生类访问，但是可以通过调用基类的**公有**和**保护**成员来访问。
- **保护继承（protected）：** 当一个类派生自**保护**基类时，基类的**公有**和**保护**成员将成为派生类的**保护**成员。
- **私有继承（private）：**当一个类派生自**私有**基类时，基类的**公有**和**保护**成员将成为派生类的**私有**成员。

#### 多继承
多继承即一个子类可以有多个父类，它继承了多个父类的特性。
```C++
class <派生类名>:<继承方式1><基类名1>,<继承方式2><基类名2>,…
{
	<派生类类体>
};
```

## 2.3 多态
多态（Polymorphism）是 C++ 面向对象编程的重要特性之一，指同一个接口可以根据对象类型表现出不同的行为。
例如，狗和猫都属于动物，它们都有发出声音的行为，但狗会汪汪叫，猫会喵喵叫。

在 C++ 中，可以定义一个动物基类 `Animal`，再创建 `Dog` 和 `Cat` 派生类。通过基类提供的统一接口，就可以调用不同动物各自的行为。

C++ 多态主要分为两种：
- **编译时多态（静态多态）：** 在编译阶段确定调用的函数，例如函数重载、运算符重载和模板。
- **运行时多态（动态多态）：** 通过虚函数和继承机制，在运行时根据对象的实际类型选择函数实现。

#### 多态的基本原理
在 C++ 中，实现运行时多态通常需要满足以下条件：
1. 存在基类与派生类的继承关系。
2. 基类声明了虚函数（`virtual`）。
3. 派生类重写了对应的虚函数。
4. 通过基类指针或引用调用虚函数。
```C++
// 动物基类
class Animal {
public:
    // 定义虚函数
    virtual void sound() const {
        cout << "Animal makes a sound" << endl;
    }

    // 虚析构函数
    virtual ~Animal() = default;
};

// 狗类
class Dog : public Animal {
public:
    // 重写基类虚函数
    void sound() const override {
        cout << "Dog barks" << endl;
    }
};

// 猫类
class Cat : public Animal {
public:
    void sound() const override {
        cout << "Cat meows" << endl;
    }
};

int main() {
    Dog dog;
    Cat cat;

    // 基类指针指向不同的派生类对象
    Animal* animal = &dog;
    animal->sound();

    animal = &cat;
    animal->sound();

    return 0;
}
```
#### 代码分析
**1、定义基类**
`Animal` 类定义了虚函数 `sound()`，允许派生类提供不同的实现。
**2、派生类重写虚函数**
`Dog` 和 `Cat` 都继承自 `Animal`，并使用 `override` 重写 `sound()`。
**3、通过基类指针调用函数**
当基类指针指向 `Dog` 对象时，调用 `Dog::sound()`；当它指向 `Cat` 对象时，调用 `Cat::sound()`。
因此，即使调用代码相同，程序仍然可以根据对象的实际类型执行不同的函数。
**注意：** 实例使用栈上创建的对象，不需要通过 `new` 和 `delete` 手动管理内存。

### 2.3.1 虚函数
虚函数（Virtual Function）是在基类中使用 `virtual` 关键字声明的非静态成员函数。地址晚绑定
派生类可以重写虚函数，使程序在通过基类指针或引用调用该函数时，根据对象的动态类型选择对应的实现。
例如：
```C++
class Base {
public:
    virtual void show() {
        // 基类实现
    }
}
```
**虚函数具有以下特点：** 
- 可以在基类中提供默认实现。
- 派生类可以选择是否重写。
- 通过基类指针或引用调用时，可以发生动态绑定。
- 派生类中的对应重写函数仍然是虚函数，即使没有再次写出 `virtual`。

**没有 virtual 会怎样？** 
如果基类成员函数没有声明为虚函数，那么通过基类指针调用该函数时，通常根据指针的静态类型确定调用哪个版本。
因为基类中的 `sound()` 不是虚函数，所以 `animal->sound()` 调用的是基类版本。
如果在基类的 `sound()` 前添加 `virtual`，那么通过基类指针调用时，就可以选择派生类的重写版本。

#### override 关键字
从 C++11 开始，可以使用 `override` 明确声明派生类函数用于重写基类虚函数。
```C++
class Base {
public:
    virtual void show() const {}
};

class Derived : public Base {
public:
    void show() const override {}
};
```
`override` 不是实现动态绑定的必要条件，但建议在重写虚函数时使用。

#### final 关键字
从 C++11 开始，可以使用 `final` 禁止派生类进一步重写某个虚函数，或者禁止其他类继续继承某个类。
```C++
class Base {
public:
    virtual void show() {}
};

class Derived : public Base {
public:
    void show() final {}
};
```
以上代码中，`Derived::show()` 不能被更下层的派生类重写。
如果将 `final` 用于类：
```C++
class Dog final {
public:
	void sound() {}
};
```
那么 `Dog` 不能再作为其他类的基类。


#### 动态绑定
动态绑定（Dynamic Binding），也称为运行时绑定，是指虚函数调用的具体实现可以在程序运行时根据对象的动态类型确定。
与之相对的是静态绑定（Static Binding），即在编译阶段确定函数调用的目标。

|对比项|静态绑定|动态绑定|
|---|---|---|
|确定时机|编译阶段|运行阶段|
|常见场景|普通成员函数、函数重载|通过基类指针或引用进行虚函数调用|
|是否需要虚函数|不需要|通常需要|
|主要特点|调用目标通常可以直接确定|根据对象动态类型选择实现|

需要注意，虚函数调用不一定都必须在运行时进行动态查找。编译器在能够确定目标的情况下，也可能进行去虚拟化（Devirtualization）等优化


### 2.3.2 虚析构函数
如果一个类作为多态基类使用，并且允许通过基类指针删除派生类对象，通常应该将基类析构函数声明为 `virtual`。(为了删除派生类对象)
只要你的类有可能被作为基类使用时，就应该把基类的析构函数声明为虚函数，这样可以避免派生类出现资源泄漏的问题
这样可以确保删除派生类对象时，正确执行派生类和基类的析构过程。

调用 `delete animal` 时，会先执行 `Dog` 的析构函数，再执行 `Animal` 的析构函数。
**注意：**如果基类析构函数不是虚函数，通过基类指针删除派生类对象通常会产生未定义行为，而不只是简单地导致内存泄漏。
在现代 C++ 中，通常建议优先使用局部对象或智能指针管理资源，减少手动使用 `new` 和 `delete`。


### 2.3.3 纯虚函数
纯虚函数本质是一份“标准化接口契约”，它解决的最核心问题是“子类不按规矩办事”，核心作用是确保子类都遵循统一的接口标准，确保所有子类都按照统一的标准实现功能。它强制所有子类都必须实现所有纯虚函数。

**核心作用：** 定义一套统一接口规范，强制所有派生类都接受这套规范，规定了派生类必须实现哪些功能
**基本语法：** 纯虚函数（Pure Virtual Function）是在虚函数声明后使用 `= 0` 指定的函数。
```C++
virtual 返回类型 函数名(参数列表) = 0;
```


### 2.3.4 抽象基类
抽象基类就是包含纯虚函数的类，它是纯虚函数的载体，专门用来定义接口规范的。它只负责定义功能，不管怎么实现功能，把具体的实现交给派生类去做。
**注意：** 
1. 抽象基类不能直接创建对象。因为它里面的纯虚函数没有实现
2. 抽象基类只能作为基类使用，它就像一个模板，专门给其它类继承，让派生类去实现它定义的接口
3. 可以声明抽象基类的指针或引用指向派生类对象，实现多态。
4. 抽象类会强制派生类实现它的接口，如果派生类没有实现抽象类中的所有纯虚函数，那么这个派生类也会变成抽象类，同样不能创建对象


### 虚函数与纯虚函数的区别

| 对比项       | 虚函数                    | 纯虚函数                       |
| --------- | ---------------------- | -------------------------- |
| 声明方式      | `virtual void show();` | `virtual void show() = 0;` |
| 是否允许提供实现  | 允许                     | 允许在类外提供定义                  |
| 派生类是否必须重写 | 不必须                    | 具体派生类必须提供非纯的最终重写版本         |
| 是否使类成为抽象类 | 不会仅因为普通虚函数而成为抽象类       | 若存在未实现的纯虚函数，则属于抽象类         |
| 主要用途      | 提供可重写的行为               | 定义必须由具体派生类实现的接口            |

## 2.4 重载
C++ 允许在同一作用域中的某个**函数**和**运算符**指定多个定义，分别称为**函数重载**和**运算符重载**。
重载声明是指一个与之前已经在该作用域内声明过的函数或方法具有相同名称的声明，但是它们的参数列表和定义（实现）不相同。
当您调用一个**重载函数**或**重载运算符**时，编译器通过把您所使用的参数类型与定义中的参数类型进行比较，决定选用最合适的定义。选择最合适的重载函数或重载运算符的过程，称为**重载决策**。

**重载函数：** 
在同一个作用域内，可以声明几个功能类似的同名函数，但是这些同名函数的形式参数（指参数的个数、类型或者顺序）必须不同。您不能仅通过返回类型的不同来重载函数。
```C++
class printData
{
   public:
      void print(int i) {
        cout << "整数为: " << i << endl;
      }
      void print(double  f) {
        cout << "浮点数为: " << f << endl;
      }
      void print(char c[]) {
        cout << "字符串为: " << c << endl;
      }
};
```

**重载运算符：** 
您可以重定义或重载大部分 C++ 内置的运算符。这样，您就能使用自定义类型的运算符。
重载的运算符是带有特殊名称的函数，函数名是由关键字 operator 和其后要重载的运算符符号构成的。与其他函数一样，重载运算符有一个返回类型和一个参数列表。
```C++
// 重载 + 运算符，用于把两个 Box 对象相加 
Box operator+(const Box& b) 
{ 
	Box box; 
	box.length = this->length + b.length; 
	box.breadth = this->breadth + b.breadth; 
	box.height = this->height + b.height; 
	return box; 
}

Application& operator= (const Application&) = delete 
```

### 3.1 单例模式
单例模式是一种设计模式，确保一个类只有一个实例，不能有多个实例，并提供全局访问点。比如：整个智能家居系统中只能有一个主控制器，如果有多个控制器，就会出现命令冲突。单例模式就可以保证整个系统只有一个主控制器实例。
**核心思想：** 将构造函数私有化，通过静态成员函数创建和获取实例
```C++
Application::getInstance();
/* 就是说getINstance(),这个函数属于Application这个类的作用域，你要去Application这个类里面找这个函数。如果不这样编译器就可以把它和其他同名的函数混淆 */
/* 1. 把Application类的构造函数私有化，这样外部就不能直接创建Application的对象了
   2. 提供一个静态成员函数getInstance是，用来创建和获取唯一的Application实例
   3. 当第一次调用getInstance()时，创建一个Application实例并保存起来；以后再调用getInstance()时，直接返回之前创建的实例。
   这样就保证了整个应用程序只有一个Application实例，避免了多个实例导致的资源冲突和状态不一致
*/
```

**优势：** 
1. **避免资源冲突：** 有限资源（数据库连接、文件句柄等）只能被一个对象独占，避免冲突和竞争。如果创建多个对象，它们可能同时操作同一个资源，导致资源冲突或数据混乱
2. **保证全局状态统一：** 所有模块使用同一个对象，确保全局状态一致，避免出现不一致的程序行为。如果有很多模块，每个模块都需要访问全局配置，那单例模式可以确保每个模块看到的配置都是一样的。如果每个模块都创建自己的配置对象，可能出现有的模块用新配置，有的用旧配置的情况，导致程序行为不一致
3. **避免重复初始化：** 所有模块共享一个模块，且对象只初始化一次，避免重复加载配置等耗时操作，提高程序启动效率
4. **懒加载：** 在程序启动的时候不创建对象，在第一次调用GetInstance()的时候才创建对象。节省程序启动时间和内存资源
5. **全局访问点：** 单例模式提供了一个全局访问点，你可以在任何地方通过GetInstance()来获取单例对象，不用传递对象指针或引用

**实现：** 
把构造函数、析构函数、拷贝构造函数、赋值运算符都私有化。用静态方法(GetInstance)访问私有构造函数，确保一个只能创建一个类。外部无法直接调用私有构造函数，只能通过静态方法获取实例。禁止拷贝。
通过静态成员变量存储唯一实例，第一次调用时创建，之后直接返回

**静态成员变量与非静态成员变量的区别：** 
**静态成员变量：** 属于类本身，全局只有一份，所有对象共享
**非静态成员变量：** 属于对象实例，每个对象都有自己的一份，互不影响
**静态方法与非静态方法的区别：** 
**静态方法：** 属于类本身，不需要通过对象实例来调用，可以直接通过类名调用。静态方法只能访问类的静态成员，不能访问非静态成员，因为静态方法没有this指针，不知道访问哪个成员
**非静态方法：** 属于对象实例，必须通过对象实例调用，非静态方法可以访问静态成员和非静态成员

**单例模式为什么需要静态成员变量和静态方法：** 
1. **全局唯一：** 确保实例只有一个
2. **生命周期长：** 静态成员变量的生命周期和程序一样长，从程序启动到结束，确保实例一直存在
3. **无需对象实例即可访问：** 而静态方法可以通过类名访问而创建实例，而单例模式的构造函数是私有的，不是静态方法无法访问私有的构造函数，自然就无法创建实例

```C++
class Application {
public:
    /* 获取应用程序实例：首次调用时创建实例，不是第一次调用时返回之前的实例 */
    static Application& GetInstance()
    {
        static Application instance;
        return instance;
    }
    // 删除拷贝构造函数和赋值运算符，禁止拷贝构造和拷贝赋值(=delete 显示禁止)
    Application(const Application&) = delete; //显示删除函数，表示这个函数不允许调用，一旦调用直接报错
    Application& operator=(const Application&) = delete;

private:
    Application();
    ~Application();
```

### 3.2 工厂模式
工厂模式就是一种“按需生产”的设计模式，它隐藏了对象创建的具体细节，只对外提供统一的创建接口，你只需要告诉它想什么，它就会给你对应的对象，不需要知道对象是怎么生产出来的
**优势：** 1. 解耦软件和硬件：软件不需要关心硬件细节，同一套代码可以适配不同硬件
      2. 提高代码的可维护性：硬件细节都封装在工厂函数中，修改硬件只需要修改工厂函数，不需要修改业务代码

### 3.3 模板
**模板：** 泛型编程的核心，解决逻辑相同、仅类型不同带来的重复编码问题
**核心思想：** 把类型变成参数，编写一次通用代码，让编译器在编译期，根据传入的不同类型，自动生成多份版本的代码

**函数模板：** 
```C++
template <模板参数列表>
```

## 3.4 STL
**STL：** 标准模板库，是C++标准库里面那一大套基于模板写好的通用组件。它提供了一套可复用的、通用、高性能、标准化的数据结构+配套算法，不用开发者重复造轮子；依托模板做到一份结构/算法支持任意满足条件的类型
STL 的设计基于泛型编程，这意味着使用模板可以编写出独立于任何特定数据类型的代码。STL就是基于模板写出来的一堆通用容器、算法
STL 分为多个组件，包括容器（Containers）、迭代器（Iterators）、算法（Algorithms）、函数对象（Function Objects）和适配器（Adapters）等。
**STL容器：** 存数据的（如：向量（vector）、链表（list）、队列（queue）、栈（stack）、集合（set）、映射（map）等）
使用 STL 的好处:
- **代码复用**：STL 提供了大量的通用数据结构和算法，可以减少重复编写代码的工作。
- **性能优化**：STL 中的算法和数据结构都经过了优化，以提供最佳的性能。
- **泛型编程**：使用模板，STL 支持泛型编程，使得算法和数据结构可以适用于任何数据类型。
- **易于维护**：STL 的设计使得代码更加模块化，易于阅读和维护。


#### 3.4.1 vector 向量
**vector：** 本质上是一个**可自动扩容的动态数组**，与传统数组相比，vector 不需要手动管理内存，可以根据元素数量自动扩容。
**vector 的核心特点:** 
- **动态大小：** vector 可以自动扩容和缩容。
- **连续内存：** 元素在内存中连续存储，访问效率非常高。
- **随机访问：** 支持通过下标快速访问元素，时间复杂度为 O(1)。
- **自动内存管理：** 不需要手动 malloc/free。
- **支持迭代器：** 可以方便地与 STL 算法配合使用。

```C++
//声明一个 vector
std::vector<int> myVector;   
// 添加元素：
myVector.push_back(10);   
// 访问元素：  
int firstElement = myVector[0];  
//获取元素数量： 
size_t size = myVector.size();
//清空 vector：
myVector.clear();

//使用下标访问：
int x = vec[0];   // [] 不检查越界，速度更快。
//使用 at()访问：
int y = vec.at(1);  //at() 会检查越界，更安全。
```

**vector 扩容机制**
当 vector 空间不足时，会发生扩容：
1. 申请更大的内存
2. 复制旧元素
3. 释放旧内存
这个过程代价较高。

**reserve() 预分配空间** 
为了避免频繁扩容，可以提前分配内存：
```C++
std::vector<int>vec;
vec.reserve(1000000);
```
这样可以减少：
- 内存重新分配
- 元素复制
- 性能损耗
这是工程开发中非常重要的优化技巧。

#### 3.4.2 queue 队列
队列是一种先进先出（FIFO, First In First Out）的数据结构，它允许在一端添加元素（称为队尾），并在另一端移除元素（称为队首）。
```C++
std::queue<Type> q;  // 声明队列
```
**常用操作：** 
- `empty()`: 检查队列是否为空。
- `size()`: 返回队列中的元素数量。
- `front()`: 返回队首元素的引用。
- `back()`: 返回队尾元素的引用。
- `push()`: 在队尾添加一个元素。
- `pop()`: 移除队首元素。

#### 3.4.3 deque 双端队列 
双端队列是一种允许在两端进行插入和删除操作的线性数据结构。
`<deque>` 是一个动态数组，它提供了快速的随机访问能力，同时允许在两端进行高效的插入和删除操作。这使得 `<deque>` 成为处理需要频繁插入和删除元素的场景的理想选择。
```C++
    std::deque<int> myDeque; // 创建一个整数类型的双端队列
```
下面是 std::deque 容器的一些常用成员函数：

### 3.5 RAII
**RAII：** 资源获取即初始化，把资源的申请放到构造函数里，把资源的释放放在析构函数。依靠对象的生命周期（或者是作用域）自动管理资源。

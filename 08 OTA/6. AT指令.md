# ESP-AT 全面详解
ESP-AT 是乐鑫（Espressif）为 ESP8266、ESP32、ESP32-S2/S3、ESP32-C2/C3/C6 等芯片提供的**官方 AT 指令集固件**。**它让 ESP 芯片变成一个可通过串口控制的 Wi-Fi/蓝牙通信模块：主控 MCU 或 PC 只需发送文本形式的 AT 命令，就能完成 Wi-Fi 连接、TCP/UDP 通信、MQTT、HTTP、BLE 等操作，而不需要在主控上实现复杂网络协议栈。

下面从概念、架构、硬件、命令、模式、示例、排错等方面系统讲解。

---
## 1. ESP-AT 是什么
- **AT 命令**：源自 Hayes 调制解调器命令，通常以 `AT` 开头，以 `\r\n` 结尾。
- **ESP-AT**：运行在 ESP 芯片上的固件，内部包含：
  - AT 命令解析器
  - Wi-Fi 协议栈
  - 蓝牙/BLE 协议栈
  - TCP/IP 协议栈
  - MQTT、HTTP、WebSocket、SSL/TLS 等应用协议
  - 系统、电源、OTA、文件系统等管理功能
- **角色**：**ESP 芯片作为“通信协处理器”，主控 MCU 作为“主机”。主机通过 UART、SPI 等接口发送 AT 命令，ESP 执行后返回结果。**
- **典型应用**：STM32、Arduino、51 单片机、PLC、Linux 小板等通过串口接入 Wi-Fi/蓝牙。

---
## 2. 核心架构与工作原理

```
主控 MCU / PC / 串口工具
		|
        │  UART / SPI / SDIO
        ▼
┌──────────────────────────┐
│ ESP 芯片运行 ESP-AT 固件   │
│  ├─ AT 命令解析           │ 
│  ├─ Wi-Fi / BT 协议栈     │
│  ├─ TCP/IP 协议栈         │
│  └─ MQTT / HTTP / SSL ...│
└──────────────────────────┘
        │
        ▼
   Wi-Fi / 蓝牙 / 以太网? / 互联网
```

主机发送的典型命令：
```text
AT+CWMODE=1
OK
AT+CWJAP="MySSID","MyPassword"
WIFI CONNECTED
WIFI GOT IP
OK
```

ESP-AT 固件基于 ESP-IDF（ESP32 系列）或 ESP8266 RTOS SDK 构建，因此也可以下载源码自行裁剪、增加自定义命令。

## 3. 支持芯片与固件
ESP-AT 支持多类芯片，但不同芯片支持的功能不同：

| 芯片系列     | 无线能力                             | 备注                |
| -------- | -------------------------------- | ----------------- |
| ESP8266  | Wi-Fi 2.4 GHz                    | 无蓝牙，经典 AT 固件      |
| ESP32    | Wi-Fi 2.4 GHz + 经典蓝牙 + BLE       | 功能最全              |
| ESP32-S2 | Wi-Fi 2.4 GHz                    | 无蓝牙               |
| ESP32-S3 | Wi-Fi 2.4 GHz + BLE              | 无经典蓝牙             |
| ESP32-C2 | Wi-Fi 2.4 GHz + BLE              | 低成本               |
| ESP32-C3 | Wi-Fi 2.4 GHz + BLE              | RISC-V            |
| ESP32-C6 | Wi-Fi 6 2.4 GHz + BLE + 802.15.4 | 具体 AT 支持以官方固件列表为准 |

注意：
- ESP8266 不支持 5 GHz Wi-Fi。
- ESP32-S2 无蓝牙。
- ESP32-C2/C3/S3 通常无经典蓝牙。
- 不同芯片的 AT 命令集、固件版本、默认引脚可能不同。

官方资源：
- ESP-AT 文档：`https://docs.espressif.com/projects/esp-at/zh_CN/latest/`
- 源码：`https://github.com/espressif/esp-at`
- 预编译固件：官方文档中的 “AT Binary Lists”

## 4. 获取与烧录

### 4.1 使用预编译固件
适合快速验证。根据芯片型号、模组型号、Flash 大小下载对应固件，使用：
- Flash Download Tools
- esptool.py
- 官方烧录工具

烧录时通常需要：
- GPIO0 拉低进入下载模式
- 复位芯片
- 烧录完成后 GPIO0 拉高
- 再次复位运行
ESP芯片在上电或复位时，会根据特定GPIO引脚的电平状态来决定启动的模式
### 4.2 源码构建
```bash
git clone --recursive https://github.com/espressif/esp-at.git
cd esp-at
./build.py menuconfig
./build.py
```
构建前需安装匹配版本的 ESP-IDF 或 ESP8266 RTOS SDK。可在 menuconfig 中选择：
- 芯片型号
- 模组型号
- AT 命令集
- UART 引脚、波特率
- 是否启用蓝牙、MQTT、HTTP 等

## 5. 硬件连接与串口参数

### 5.1 默认串口
常见默认：
- 波特率：`115200`
- 数据位：`8`
- 校验：`None`
- 停止位：`1`
- 流控：无

常见默认 UART0 引脚：

| 芯片          | TX     | RX     |
| ----------- | ------ | ------ |
| ESP8266     | GPIO1  | GPIO3  |
| ESP32       | GPIO1  | GPIO3  |
| ESP32-C3    | GPIO21 | GPIO20 |
| ESP32-S2/S3 | GPIO43 | GPIO44 |

以具体模组和固件配置为准。

### 5.2 接线
- ESP 的 TX 接 USB-TTL 的 RX
- ESP 的 RX 接 USB-TTL 的 TX
- GND 共地
- 供电 3.3 V，电流能力要足够，Wi-Fi 发射峰值可能超过 500 mA
- ESP32 正常启动：EN 高，GPIO0 高
- ESP8266 正常启动：CH_PD/EN 高，GPIO0 高，GPIO15 低
- 不要将 5 V 直接接到 IO 引脚

### 5.3 串口工具设置
使用 PuTTY、SecureCRT、minicom、串口助手、Arduino Serial Monitor 等：
- 选择正确 COM 口
- 115200 8N1
- 发送新行：`\r\n`
- 可开启本地回显便于观察

上电后通常输出 `ready`，此时可发送 `AT`，应返回 `OK`。

## 6. AT 命令语法与响应

### 6.1 基本格式
```text
AT+<CMD>=<参数1>,<参数2>,...
AT+<CMD>?
AT+<CMD>=?
AT+<CMD>
```

- `AT+<CMD>=...`：设置参数
- `AT+<CMD>?`：查询当前值
- `AT+<CMD>=?`：查询参数范围
- `AT+<CMD>`：执行命令
- 字符串参数用双引号，如 `"SSID"`
- 参数用逗号分隔
- 特殊字符可用反斜杠转义，如 `\"`、`\,`、`\\`
- 每条命令以 `\r\n` 结束

### 6.2 常见响应
- `OK`：成功
- `ERROR`：失败
- `FAIL`：失败
- `busy`：忙
- `ready`：启动完成
- `SEND OK` / `SEND FAIL`：发送结果
- `WIFI CONNECTED` / `WIFI GOT IP` / `WIFI DISCONNECT`
- `CONNECT` / `CLOSED`
- `+IPD,<len>:<data>`：收到 TCP/UDP 数据
- `+MQTTSUBRECV:...`：收到 MQTT 消息
- `+HTTPCLIENT:...`：HTTP 客户端响应

### 6.3 `_CUR` 与 `_DEF`
新版 ESP-AT 常用：
- `_CUR`：当前生效，不保存到 Flash
- `_DEF`：默认值，保存到 Flash，重启后生效
- `AT+SYSSTORE`：控制参数是否自动保存

例如：
```text
AT+UART_CUR=921600,8,1,0,0
AT+UART_DEF=115200,8,1,0,0
```

## 7. 常用命令分类

以下为常见命令，具体以对应芯片和固件版本的 AT 命令集为准。

### 7.1 基础系统命令

| 命令            | 作用        |
| ------------- | --------- |
| `AT`          | 测试通信      |
| `AT+GMR`      | 查询版本      |
| `AT+RST`      | 重启        |
| `AT+RESTORE`  | 恢复出厂设置    |
| `AT+E`        | 开关回显      |
| `AT+UART_CUR` | 设置当前 UART |
| `AT+UART_DEF` | 设置默认 UART |
| `AT+SLEEP`    | 睡眠模式      |
| `AT+GSLP`     | 深度睡眠      |
| `AT+SYSSTORE` | 参数存储模式    |
| `AT+SYSMSG`   | 系统消息控制    |
| `AT+SYSRAM`   | 查询内存      |

### 7.2 Wi-Fi 命令

| 命令 | 作用 |
|---|---|
| `AT+CWMODE` | Station / SoftAP / 共存 |
| `AT+CWJAP` | 连接 AP |
| `AT+CWLAP` | 扫描 AP |
| `AT+CWQAP` | 断开 AP |
| `AT+CWSAP` | 配置 SoftAP |
| `AT+CWDHCP` | DHCP 设置 |
| `AT+CIPSTA` | Station IP 设置/查询 |
| `AT+CIPAP` | SoftAP IP 设置/查询 |
| `AT+CWSTARTSMART` | 智能配网 |
| `AT+CWSTOPSMART` | 停止智能配网 |

示例：
```text
AT+CWMODE=1
OK
AT+CWJAP="MySSID","MyPassword"
WIFI CONNECTED
WIFI GOT IP
OK
AT+CIPSTA?
+CIPSTA:ip:"192.168.1.100"
+CIPSTA:gateway:"192.168.1.1"
+CIPSTA:netmask:"255.255.255.0"
OK
```

### 7.3 TCP/IP 命令

| 命令 | 作用 |
|---|---|
| `AT+CIPSTATUS` | 查询连接状态 |
| `AT+CIPMUX` | 单连接/多连接 |
| `AT+CIPSTART` | 建立 TCP/UDP/SSL 连接 |
| `AT+CIPSEND` | 发送数据 |
| `AT+CIPSENDEX` | 扩展发送 |
| `AT+CIPCLOSE` | 关闭连接 |
| `AT+CIPSERVER` | 创建 TCP 服务器 |
| `AT+CIPMODE` | 普通/透传模式 |
| `AT+CIPRECVMODE` | 主动/被动接收 |
| `AT+CIPRECVDATA` | 被动读取数据 |
| `AT+CIPRECVLEN` | 查询接收缓存长度 |
| `AT+PING` | Ping |
| `AT+CIPDNS` | DNS 设置 |

单连接示例：
```text
AT+CIPMUX=0
OK
AT+CIPSTART="TCP","example.com",80
CONNECT
OK
AT+CIPSEND=18
>
GET / HTTP/1.0\r\n\r\n
SEND OK
+IPD,...
CLOSED
```

多连接示例：
```text
AT+CIPMUX=1
OK
AT+CIPSTART=0,"TCP","example.com",80
0,CONNECT
OK
AT+CIPSEND=0,5
>
hello
SEND OK
```

接收格式：
- 单连接：`+IPD,<len>:<data>`
- 多连接：`+IPD,<link ID>,<len>:<data>`

### 7.4 SSL/TLS
```text
AT+CIPSTART="SSL","example.com",443
```
可通过 `AT+CIPSSLCONFIG` 配置 CA、证书、密钥等。MQTT over TLS、HTTPS 也依赖 SSL 功能。TLS 握手消耗内存较大，低内存芯片需注意。

### 7.5 MQTT
常见命令：
```text
AT+MQTTUSERCFG=0,1,"client_id","username","password",0,0,""
AT+MQTTCONN=0,"broker.emqx.io",1883,0
AT+MQTTSUB=0,"test/topic",1
AT+MQTTPUB=0,"test/topic","hello",1,0
AT+MQTTUNSUB=0,"test/topic"
AT+MQTTCLEAN=0
```
收到消息：
```text
+MQTTSUBRECV:0,"test/topic",5,hello
```

### 7.6 HTTP / WebSocket
HTTP 客户端通常使用：
```text
AT+HTTPCLIENT=...
```
可发起 GET/POST，支持 HTTP/HTTPS。具体参数顺序因版本而异。

WebSocket 常见：
```text
AT+WSCFG=...
AT+WSCONN=...
AT+WSSEND=...
AT+WSCLOSE
```

### 7.7 蓝牙 BLE 与经典蓝牙
BLE 常见命令：
```text
AT+BLEINIT=2
AT+BLENAME="ESP-AT"
AT+BLEGATTSSRVCRE
AT+BLEGATTSSRVSTART
AT+BLEADVSTART
AT+BLEADVSTOP
AT+BLEGATTSNTFY=...
AT+BLEGATTCREAD=...
AT+BLEGATTCWRITE=...
```
经典蓝牙常见：
```text
AT+BTINIT=1
AT+BTNAME="ESP-AT"
AT+BTSTARTDISC
AT+BTPAIR=...
AT+BTSPPSTART
```
注意：ESP8266、ESP32-S2、ESP32-C2/C3/S3 等通常不支持经典蓝牙。

### 7.8 SNTP、mDNS、OTA、睡眠
SNTP：
```text
AT+CIPSNTPCFG=1,8,"ntp.aliyun.com"
AT+CIPSNTPTIME?
```
mDNS：
```text
AT+MDNS=1,"esp-at","_http","_tcp",80
```
OTA：部分固件支持 `AT+CIUPDATE` 或 `AT+OTA`，用于从服务器升级固件。
睡眠：
```text
AT+SLEEP=1
AT+GSLP=10000
```

## 8. 工作模式详解

### 8.1 命令模式
默认模式，主机发送 `AT+...`，ESP 返回响应。适合控制、配置、短数据。

### 8.2 透传模式
适合串口转 Wi-Fi。设置：
```text
AT+CIPMODE=1
OK
AT+CIPSEND
>
```
进入 `>` 后，串口输入的数据会直接发送到 TCP/UDP。退出透传需发送 `+++`：
- `+++` 前后需有静默时间，通常约 20 ms
- `+++` 后不要立即跟回车
- 透传通常只支持单连接

### 8.3 单连接与多连接
- `AT+CIPMUX=0`：单连接，最多一个 TCP/UDP 连接
- `AT+CIPMUX=1`：多连接，通常支持 0~4 或 0~5 号连接
- 多连接发送：`AT+CIPSEND=<link ID>,<len>`
- 多连接接收：`+IPD,<link ID>,<len>:<data>`

### 8.4 主动接收与被动接收
- 主动接收：收到数据直接输出 `+IPD`
- 被动接收：
  ```text
  AT+CIPRECVMODE=1
  AT+CIPRECVLEN?
  AT+CIPRECVDATA=<len>
  ```
适合主机处理速度慢、需要控制读取节奏的场景。

## 10. 常见问题排查

| 现象              | 可能原因               | 处理                                 |
| --------------- | ------------------ | ---------------------------------- |
| 发送 AT 无响应       | 波特率错、接线错、未共地、固件未运行 | 检查 115200 8N1、TX/RX 交叉、供电、EN/GPIO0 |
| 返回乱码            | 波特率不匹配、时钟错误        | 重新确认波特率，检查晶振/模组配置                  |
| 上电无 `ready`     | 启动模式不对、固件损坏        | GPIO0 高、EN 高，重新烧录                  |
| Wi-Fi 连不上       | 非 2.4G、密码错、信号弱     | 使用 2.4G AP，检查密码和信号                 |
| TCP 连接失败        | DNS、端口、服务器、网络      | 用 `AT+PING` 测试，检查服务器               |
| `AT+CIPSEND` 失败 | 未连接、长度错、多连接未指定 ID  | 检查 `AT+CIPSTATUS`，长度必须准确           |
| 透传无法退出          | `+++` 格式或静默时间不对    | 前后静默约 20 ms，不要带回车                  |
| 模块反复重启          | 供电不足               | 使用 3.3V 大电流 LDO，加电容                |
| 命令返回 ERROR      | 固件不支持、参数错、模式不对     | 查对应版本 AT 命令集                       |
| 数据丢失            | 无流控、波特率过高          | 降低波特率或启用 RTS/CTS 硬件流控              |

## 11. 优缺点与适用场景

### 优点
- 简单：主控只需串口，无需移植 Wi-Fi/蓝牙协议栈
- 快速：适合原型验证和中小型物联网设备
- 成熟：官方维护，支持芯片多，协议丰富
- 灵活：支持 TCP/UDP/SSL/MQTT/HTTP/BLE 等
- 可定制：可基于源码裁剪功能、增加命令

### 缺点
- 性能和灵活性不如直接开发 ESP-IDF
- AT 命令解析有开销，延迟较高
- 高吞吐、低延迟场景不占优
- 功能受固件版本限制
- 需要额外主控或串口，增加成本

### 适用场景
- MCU 联网：STM32、Arduino、51 等接入 Wi-Fi
- 串口转 Wi-Fi / 蓝牙
- 智能家居、传感器上传
- 快速连接云平台：MQTT、HTTP
- 工业数据采集、远程控制
- 蓝牙网关、BLE 设备调试

## 12. 版本与学习注意事项

1. **不同芯片命令集不同**：ESP8266、ESP32、ESP32-C3 等支持的命令有差异。
2. **不同 AT 版本命令有差异**：2.x 与 3.x 在 `_CUR`、`_DEF`、MQTT、HTTP 等命令上可能不同。
3. **默认引脚和波特率可能不同**：以具体模组和固件配置为准。
4. **字符串转义**：SSID、密码、Topic 中若含逗号、引号、反斜杠，需要转义。
5. **长度必须准确**：`AT+CIPSEND=<len>` 的 `len` 是实际字节数。
6. **异步消息要处理**：主机程序应能解析 `+IPD`、`WIFI CONNECTED`、`CLOSED` 等主动上报。
7. **推荐阅读官方文档**：
   - ESP-AT 用户指南
   - 对应芯片的 “AT 命令集”
   - AT Binary Lists 固件列表
   - GitHub `espressif/esp-at`

## 总结
ESP-AT 是乐鑫官方提供的 AT 固件方案，把 ESP 芯片变成易用的 Wi-Fi/蓝牙模块。它通过 UART 等接口接收 AT 命令，支持 Wi-Fi、TCP/UDP、SSL、MQTT、HTTP、WebSocket、BLE、SNTP、OTA 等功能。开发时重点掌握：

- 硬件接线与串口参数
- AT 命令格式与响应
- Wi-Fi 连接与 TCP/UDP 通信
- 单连接、多连接、透传、被动接收
- MQTT/HTTP/BLE 等应用协议
- 版本差异与常见排错

对于需要快速让主控联网、又不想深入 Wi-Fi 协议栈的项目，ESP-AT 是非常实用的选择；对于高性能、复杂应用，则建议直接使用 ESP-IDF 开发。

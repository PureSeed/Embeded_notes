## 1. 内存布局与上电启动链路

典型 Flash 分区：
```
0x08000000  +----------------------+
            |  Bootloader 向量表   |
            |  Bootloader 代码     |
            |  Bootloader 参数区   |
0x08008000  +----------------------+
            |  APP 向量表          |
            |  APP 代码            |
            |  APP 数据/参数        |
0x08040000  +----------------------+
            |  备份区 / 下载区      |
            +----------------------+
```

Cortex-M 上电复位时，硬件会：
1. 从 `0x00000000` 取**初始 MSP**（主栈指针）。
2. 从 `0x00000004` 取 **Reset_Handler 地址**。
3. 跳转到 Reset_Handler (复位处理函数)开始执行。

**MSP：** 本质是用来存储当前栈顶地址的32位寄存器。用于管理栈空间。
**为什么要初始化MSP？**
1. 它是函数调用的基础
2. 中断处理的基础：中断发生时，硬件需要把寄存器的值压入栈中，如果没有栈指针，就无法处理中断
3. 系统稳定的基础：初始化的栈指针可以确保栈空间不会与其他内存区域重叠，避免内存冲突

**复位处理函数的作用：** 初始化全局变量、硬件、调用main函数
由于芯片通常会把 `0x00000000` 映射到 Flash 起始地址 `0x08000000`，所以：**上电后先执行的是 Bootloader，而不是 APP。**

## 2. Bootloader 启动后做什么

Bootloader 的典型流程：
1. **基础初始化**
    - 时钟、GPIO、外设、Flash 等。   - 通常不初始化太多外设，避免和 APP 冲突。

2. **检查升级标志 / 升级请求**
    - 例如读取参数区某个标志位。
    - 或者检测按键是否按下
    - 或者等待上位机发送升级命令，超时后进入 APP。
    - 如果使用 Ymodem，Bootloader 会发送 `C`，等待上位机传输固件。

3. **如果需要升级**
    - 通过 Ymodem / OTA 接收固件。
    - 写入备份区或直接写 APP 区。
    - 做 CRC / SHA 校验。
    - 校验成功后，更新升级标志，准备跳转 APP。
    - 校验失败则保留旧 APP 或重试。
        
4. **如果不需要升级**
    - 检查 APP 区是否有效。
    - 常见检查：
        - APP 栈顶是否在合法 RAM 范围。
        - APP 复位向量是否在 APP 区范围内。
        - APP 固件 CRC 是否通过。
    - 如果 APP 无效，停留在 Bootloader，等待重新升级。

5. **跳转到 APP**
    - 关闭中断、复位外设、设置栈指针、设置向量表偏移。
    - 跳到 APP 的 Reset_Handler。

## 3. 跳转 APP 的精确步骤

这是最关键的部分。Cortex-M 跳转 APP 不是简单 `goto`，需要手动模拟一次“复位启动”。
1. **关闭所有中断：** 避免跳转过程被中断打断
2. **复位外设：** 关闭Bootloader使用的外设，避免影响APP运行
3. **设置栈指针：** 从APP向量表中读取栈顶地址，设置栈指针SP
4. **跳转到APP的Reset_Handler：** 从APP中断向量表中读取复位处理函数，跳转到APP的复位处理函数。
### 3.1 跳转前准备
```c
#define APP_ADDR  0x08008000
typedef void (*pFunction)(void);
void jump_to_app(void)
{
    uint32_t app_msp   = *(volatile uint32_t *)APP_ADDR;
    uint32_t app_reset = *(volatile uint32_t *)(APP_ADDR + 4);
    // 1. 检查 APP 是否有效
    if ((app_msp & 0x2FFE0000) != 0x20000000) {
        // 栈顶不在 RAM 范围，APP 无效
        return;
    }
    // 2. 关闭全局中断
    __disable_irq();
    // 3. 关闭 SysTick，清除中断挂起
    SysTick->CTRL = 0;
    SysTick->LOAD = 0;
    SysTick->VAL  = 0;
    for (int i = 0; i < 8; i++) {
        NVIC->ICER[i] = 0xFFFFFFFF;  // 关闭所有外部中断
        NVIC->ICPR[i] = 0xFFFFFFFF;  // 清除所有中断挂起
    }
    // 4. 可选：关闭外设、 复位外设
    // HAL_DeInit();
    // 5. 设置主栈指针为 APP 向量表第一个字
    __set_MSP(app_msp);
    // 6. 设置中断向量表偏移为 APP 地址
    SCB->VTOR = APP_ADDR;
    // 7. 取 APP 复位向量并跳转
    pFunction app_entry = (pFunction)app_reset;
    app_entry();
}
```


### 3.2 为什么这样写？

| 操作                            | 原因                                       |
| ----------------------------- | ---------------------------------------- |
| `__disable_irq()`             | 防止跳转过程中 Bootloader 的中断触发，导致跑飞。           |
| 关闭 SysTick / NVIC             | Bootloader 开的中断在 APP 中可能没有对应处理函数。        |
| `__set_MSP(app_msp)`          | APP 有自己独立的栈空间，栈顶来自 APP 向量表第一个字。          |
| `SCB->VTOR = APP_ADDR`        | 让中断向量表指向 APP 区，否则中断仍会跳到 Bootloader 的向量表。 |
| `app_reset = *(APP_ADDR + 4)` | APP 的 Reset_Handler 地址存放在向量表第二个字。        |
| `app_entry()`                 | 函数指针跳转，相当于执行 APP 的复位启动流程。                |

跳转后，APP 的 `Reset_Handler` 会执行：
- 初始化 `.data`、`.bss`
- 调用 `SystemInit`
- 调用 `__main` / `main`

## 4. APP 初始化

### 4.1 链接脚本 / IDE 设置（修改Flash起始地址）

APP 的 ROM 起始地址必须改为 `APP_ADDR`，例如：
``` 
ld
MEMORY
{
    ROM (rx)  : ORIGIN = 0x08008000, LENGTH = 256K
    RAM (rwx) : ORIGIN = 0x20000000, LENGTH = 64K
}
```

否则 APP 编译出来的复位向量、函数地址都基于 `0x08000000`，跳转后必崩。

### 4.2 设置中断向量表偏移（重定向）

APP 启动时，要在 `SystemInit` 或 `main` 最开始设置：

```c
SCB->VTOR = 0x08008000;
```

或者使用标准库：
```C
NVIC_SetVectorTable(NVIC_VectTab_FLASH, 0x8000);
```

这一步必须在**使能任何中断之前**完成。

### 4.3 中断向量表

APP 的 `startup_xxx.s` 中，向量表会链接到 APP 区起始地址。第一个字是 APP 的初始 MSP，第二个字是 APP 的 Reset_Handler。

Bootloader 跳转时设置 `MSP` 和 `VTOR`，APP 启动后中断就能正确进入 APP 的中断服务函数。

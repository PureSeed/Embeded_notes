## 无线升级（OTA）详解
无线升级可以概括为：
> **通过 Wi-Fi、蓝牙、4G/5G、LoRa、Zigbee 等无线链路，把新固件从服务器或手机传到设备端，由 Bootloader 接收、校验、写入 Flash，最后跳转到新 APP 的完整过程。**

它本质上就是 **OTA（Over-The-Air）**，与串口 OTA 的最大区别在于：**传输介质从有线串口变成了无线链路**，因此带来了**网络协议、安全、功耗、断点续传等一系列新问题。** 

---
## 1. 无线升级 vs 串口升级

|维度|串口 OTA|无线 OTA|
|---|---|---|
|**传输介质**|UART 有线|Wi-Fi / BLE / 4G / LoRa / Zigbee|
|**稳定性**|高，干扰小|受环境影响大，可能断连|
|**速率**|可达 Mbps|BLE 较低，Wi-Fi/4G 较高|
|**协议**|Ymodem / Xmodem / 自定义|HTTP / MQTT / CoAP / TFTP / BLE GATT / 自定义|
|**实现复杂度**|低|高，需网络协议栈、服务器、安全机制|
|**适用场景**|产线烧录、现场维护、救砖|远程升级、批量部署、无人值守|
|**安全要求**|物理接触，相对安全|必须加密、签名、防重放、防降级|
|**掉电风险**|可控|更高，需断点续传和回滚|

无线升级最终仍要依赖 **IAP / Bootloader** 把固件写入 Flash，只是“固件从哪里来”变成了无线下载。

---
## 2. 系统组成

一个典型的无线 OTA 系统：
```text
+-------------------+       无线链路        +----------------------+
|  云端 / 服务器    | <------------------> |   设备端             |
|                   |  Wi-Fi / 4G / BLE  |                      |
|  - 固件仓库       |                     |  - 无线模块          |
|  - 版本管理       |                     |  - Bootloader        |
|  - 升级策略       |                     |  - APP               |
|  - 差分包生成     |                     |  - Flash 分区        |
+-------------------+                    +----------------------+
        ^                                         |
        |                                         |
        |            手机 APP / 网关               |
        +-----------------------------------------+
```

| 角色                | 职责                                |
| ----------------- | --------------------------------- |
| **云端/服务器**        | 存放固件、管理版本、下发升级指令、生成差分包、记录升级结果     |
| **无线模块**          | Wi-Fi / BLE / 4G 模组，负责建立无线连接、收发数据 |
| **设备 Bootloader** | 接收固件、擦写 Flash、校验、跳转 APP           |
| **设备 APP**        | 正常运行；检查更新、触发升级、上报结果               |
| **手机 APP / 网关**   | 对 BLE 设备，手机 APP 可直接作为固件传输通道       |

## 3. 常见无线升级方式

| 方式             | 典型场景       | 特点                         |
| -------------- | ---------- | -------------------------- |
| **Wi-Fi OTA**  | 智能家居、摄像头   | 速率高，可直接从云端 HTTP/HTTPS 下载   |
| **BLE OTA**    | 手环、手表、医疗设备 | 速率低，通常由手机 APP 通过 GATT 传输固件 |
| **4G/5G OTA**  | 车联网、工业设备   | 覆盖广，可远程升级，流量成本需考虑          |
| **LoRa OTA**   | 低功耗广域网     | 速率极低，通常只传差分包或小固件           |
| **Zigbee OTA** | 智能家居 Mesh  | 通过网关转发，协议有专门 OTA Cluster   |
| **NB-IoT OTA** | 表计、传感器     | 低功耗，速率低，适合小包差分升级           |

BLE OTA 常把 Ymodem 或类似协议跑在 GATT 特征值上，相当于“无线串口”。

## 4. Flash 分区设计
无线升级对分区要求更高，常见方案：

### 4.1 备份区方案
```text
+----------------------+
|  Bootloader          |  永不升级
+----------------------+
|  参数区 / 升级标志     |
+----------------------+
|  APP 区              |  当前运行固件
+----------------------+
|  备份区 / 下载区      |  新固件先存这里
+----------------------+
```

流程：新固件先下载到备份区 → 校验 → 擦 APP → 搬运 → 跳转。

### 4.2 A/B 分区方案
```text
+----------------------+
|  Bootloader          |
+----------------------+
|  参数区              |  记录当前启动分区
+----------------------+
|  APP A 区            |  当前运行
+----------------------+
|  APP B 区            |  新固件写入
+----------------------+
```

流程：运行 A 时，新固件写 B → 校验 → 修改启动标志指向 B → 复位 → Bootloader 跳转 B。  
升级失败可回滚到 A，安全性更高。

### 4.3 差分升级
不传完整固件，只传新旧版本的差异部分。设备端用差分算法（如 bsdiff、hdiffpatch）合并成完整固件。  
优点：流量小、下载快。缺点：需额外 RAM/Flash 做合并，算法复杂。

### 4.4 断电续传
支持在传输中断后从断点处继续传输，避免重新下载整个固件

### 4.5 固件签名与校验
使用RSA、SHA等算法对固件进行签名和校验，防止固件被篡改

## 5. 完整升级流程

### 阶段一：检查更新
```text
设备 APP 运行
   |
   v
定时 / 触发检查更新
   |
   v
向服务器上报当前版本、设备型号、硬件版本
   |
   v
服务器比对，返回是否有新版本
   |
   +---- 无更新 ----> 继续运行
   |
   v
有更新，获取固件下载地址、大小、校验值、签名
```


### 阶段二：下载固件
```text
APP 或 Bootloader 发起下载
   |
   v
通过 Wi-Fi / 4G / BLE 从服务器或手机获取固件
   |
   v
分块下载，写入备份区 / B 区
   |
   v
支持断点续传：记录已下载偏移，断连后继续
   |
   v
下载完成，计算整体 CRC / SHA
   |
   v
与服务器提供的校验值比对
   |
   +---- 失败 ----> 删除备份，重新下载
   |
   v
校验成功，写入升级标志
   |
   v
复位设备
```

### 阶段三：Bootloader 校验与切换
```text
上电复位
   |
   v
Bootloader 读取升级标志
   |
   +---- 无升级 ----> 检查 APP 有效性，跳转 APP
   |
   v
有升级，检查备份区 / B 区固件
   |
   v
验证签名、CRC、版本号
   |
   +---- 失败 ----> 清除标志，回滚旧 APP
   |
   v
擦除目标 APP 区
   |
   v
搬运 / 切换分区
   |
   v
再次校验
   |
   v
清除升级标志，更新启动分区
   |
   v
复位
```

### 阶段四：运行新固件并上报
```text
复位后 Bootloader 跳转新 APP
   |
   v
新 APP 启动，初始化
   |
   v
向服务器上报升级成功、新版本号
   |
   v
如果启动失败，看门狗复位，Bootloader 回滚
```

## 6. 升级包格式
无线升级包通常包含头部和固件数据：
```text
+----------------------+
|  Magic Number        |  标识固件包
+----------------------+
|  头部版本            |
+----------------------+
|  设备型号            |
+----------------------+
|  硬件版本            |
+----------------------+
|  固件版本            |
+----------------------+
|  固件大小            |
+----------------------+
|  固件 CRC / SHA      |
+----------------------+
|  签名                |  防篡改
+----------------------+
|  固件数据            |
+----------------------+
|  结束标记            |
+----------------------+
```

Bootloader 先解析头部，检查设备型号和硬件版本是否匹配，再校验签名和 CRC，最后写 Flash。

## 7. 安全机制
无线升级暴露在开放链路中，必须考虑安全：

| 安全威胁      | 防护措施                        |
| --------- | --------------------------- |
| **窃听**    | TLS / DTLS 加密传输             |
| **篡改**    | 固件签名（RSA/ECC），Bootloader 验签 |
| **伪造服务器** | 证书校验、预置公钥                   |
| **重放攻击**  | 随机数、时间戳、序列号                 |
| **降级攻击**  | 版本号校验，禁止安装旧版本               |
| **未授权升级** | 设备认证、Token、白名单              |
| **固件泄露**  | 固件加密，设备端解密                  |

Bootloader 中通常只存 **公钥**，用私钥签名的固件才能通过验证。

---
## 8. 可靠性设计
无线链路不稳定，必须处理：

| 问题       | 方案                   |
| -------- | -------------------- |
| **断连**   | 断点续传，记录已下载偏移         |
| **丢包**   | 分块重传、ACK/NAK、超时重试    |
| **掉电**   | 备份区 / A/B 分区，升级标志持久化 |
| **升级失败** | 回滚到旧固件，看门狗复位         |
| **空间不足** | 下载前检查备份区大小           |
| **版本冲突** | 检查设备型号、硬件版本、版本号      |
| **流量成本** | 差分升级、压缩固件            |
| **低功耗**  | 分批下载、休眠续传、仅在特定时间升级   |

---
## 9. 低功耗与网络考虑
对电池设备：
- 尽量用 **BLE** 或 **NB-IoT** 等低功耗链路。
- 升级包要小，优先 **差分升级**。
- 下载可分多次，每次唤醒下载一部分，保存偏移后休眠。
- 避免在电量低时升级。
- Wi-Fi 设备可先连路由器，再从本地服务器下载，减少蜂窝流量。


对 4G/5G 设备：
- 注意流量费用，差分包可大幅降低。
- 支持 HTTP Range 断点续传。
- 服务器可限速、分时段推送。

## 10. 常见问题与排查

|现象|可能原因|排查方向|
|---|---|---|
|下载中断|网络不稳定、服务器超时|检查信号、断点续传逻辑|
|校验失败|固件包损坏、CRC 算法不一致|核对 CRC/SHA、重新下载|
|签名验证失败|公钥不对、固件未签名|检查密钥和签名流程|
|跳转 HardFault|APP 链接地址错误、VTOR 未设置|检查链接脚本和 APP 启动代码|
|升级后无法启动|升级标志未清除、分区切换错误|读参数区、检查 Bootloader|
|反复升级|版本号未更新、标志未清除|检查版本管理和标志写入|
|设备变砖|无备份区，擦 APP 时掉电|使用 A/B 分区或备份区|
|BLE 升级慢|MTU 小、连接间隔长|增大 MTU、缩短连接间隔、用 1K 块|

## 12. 一句话总结

> **无线升级（OTA）就是通过 Wi-Fi、蓝牙、4G/5G 等无线链路，把新固件从云端或手机传到设备，由 Bootloader 完成校验、写入 Flash 和跳转。它的核心难点不在“写 Flash”，而在无线链路的稳定性、安全性、断点续传、差分升级、A/B 分区和回滚机制。**
